# SADR retrieval benchmark

A comparative evaluation of the Symbolic-Assisted Dense Retriever (SADR) against dense
retrieval and Text2Cypher, on 38 questions with hand-written gold queries.

## Setup

- **Graph**: the public Neo4j *recommendations* example database
  (`recommendations-50.dump` from github.com/neo4j-graph-examples/recommendations,
  9,125 movies, 28,863 nodes), loaded into Neo4j 5.26 Community in Docker. The
  extended graph of about 120,000 nodes used for the examples in the paper is not
  distributed, so the public graph is used for reproducibility.
- **Embeddings**: `embed_imdb120k.py` (ids, `__Entity__` label, BAAI/bge-small-en-v1.5
  normalized embeddings, vector index `entity`); `User` nodes receive an `id` but no
  `__Entity__` label.
- **SADR**: `definability.py` (k = 5 seeds, beta = 0.45, one hop, at most two
  neighbours per relation), with genres in `Genre.name` and `RATED` excluded because users
  are anonymous.
- **Text2Cypher**: Qwen2.5 7B Instruct via Ollama, temperature 0, one attempt, with the
  schema in the prompt and `LIMIT 200`.

Set up the graph as described in the main README, then:

```bash
ollama pull qwen2.5:7b-instruct
PYTHONPATH=. python benchmark/run_benchmark.py
python benchmark/summarize.py
```

## Systems

| System | Description |
|---|---|
| `dense@5` | top-5 nodes of the vector index (the seeds of SADR) |
| `dense@N` | dense ranking cut at the number of movies returned by `sadr_full` (size-matched control) |
| `sadr_impl` | SADR as implemented in `definability.py`: each disjunct reduced to the seed-node conditions, `LIMIT 200` |
| `sadr_full` | as `sadr_impl`, plus the one-hop constraints that carry constants, as `EXISTS` subqueries |
| `text2cypher` | Cypher generated by the LLM from the question |

## Results (38 questions)

| System | P | R | F1 | Movies returned |
|---|---|---|---|---|
| dense@5 | 0.36 | 0.05 | 0.08 | 4 |
| dense@N | 0.12 | 0.45 | 0.15 | 283 |
| sadr_impl | 0.10 | 0.24 | 0.11 | 226 |
| sadr_full | 0.12 | 0.34 | 0.14 | 283 |
| text2cypher | 0.70 | 0.65 | 0.66 | 31 |

- SADR expands the retrieved context: recall rises from 0.05 (its seeds) to 0.34
  (Wilcoxon p < 0.001).
- It does not outperform dense retrieval of the same size: recall 0.34 vs 0.45
  (p = 0.017); F1 difference not significant.
- Keeping the one-hop constraints improves on the implemented simplification
  (+0.10 recall, p = 0.008).
- Text2Cypher is far more precise and has higher recall overall (F1 0.66), except on
  country + genre questions (recall 0.32 vs 0.53 for SADR); 5 of 38 generated queries
  fail to execute.

## Threats

- The gold queries and the Text2Cypher prompt were written by the same person; the
  prompt describes the list-valued `countries` property in the same way the gold
  queries use it.
- 38 questions in four groups; the `not-expressible` group contains constraints outside
  SADR's attribute set by design.
- One graph and one embedding model; the answer-generation step is not evaluated.
